# BendeRadio для Orange Pi One

Интернет-радио в форме головы Бендера: матрица MAX7219 5×8×8 («рот»-анализатор и «глаза»),
энкодер с кнопкой, потоковое аудио и конфиг с радиостанциями и Wi-Fi.

Это **порт ESP-прошивки на Linux**: вместо микроконтроллера — Orange Pi One (Allwinner H3),
вместо ESP32-audioI2S — `ffmpeg` + `aplay`, вместо EEPROM — JSON-файл настроек.
Логика лица, энкодера и анализатора перенесена один в один.

---

## Сначала про железо Orange Pi One (важно!)

| Чего нет в Orange Pi One | Как быть |
|---|---|
| **Wi-Fi** (плата только с Ethernet) | нужен USB Wi-Fi донгл; SSID/пароль из конфига применяются к нему (`wlan0`) |
| **Аналогового аудиовыхода** (только HDMI) | USB-звуковая карта (`hw:1,0`) или HDMI-звук; `audio.device` в конфиге |
| **АЦП / аналогового входа** | анализатор считает уровень **из самого аудиопотока** — делить сигнал не нужно |

Если у вас не «One», а Orange Pi PC/Plus/Zero с 3.5 мм разъёмом — программа та же,
поменяется только `audio.device` (`default`/`hw:0,0`) и, возможно, пины.

Всё остальное (MAX7219, энкодер) подключается к 40-пиновому разъёму.

## Что нужно установить

* Python **3.9+** (в Armbian уже есть);
* `ffmpeg` — декодирование потока;
* `alsa-utils` — `aplay` и `amixer`;
* по желанию: `python3-spidev` (быстрый SPI для матрицы), `python3-numpy`
  (программная громкость), `python3-libgpiod` (энкодер через libgpiod).

`install.sh` ставит всё сам:

```bash
sudo ./install.sh
```

Скрипт разложит программу в `/opt/benderadio`, конфиг в `/etc/benderadio/config.json`,
состояние в `/var/lib/benderadio/` и включит systemd-сервис `benderadio`.

## Быстрый старт

```bash
# 1. правим станции/пины/звук
sudo nano /etc/benderadio/config.json

# 2. проверка без железа (конфиг, шум, шрифт, VU, настройки, энкодер)
python3 /opt/benderadio/run.py --config /etc/benderadio/config.json --selftest

# 3. прогон без железа: лицо рисуется в консоль, звук синтетический
python3 /opt/benderadio/run.py --config /etc/benderadio/config.json --simulate --duration 5

# 4. боевой запуск
systemctl start benderadio
journalctl -u benderadio -f
```

Из папки проекта — то же самое, но `python3 run.py ...` и `--config config.json`.

## Тесты железа без Wi-Fi и звука

Отдельные режимы: подключаются **только к матрице и энкодеру**, сеть, `ffmpeg` и `aplay`
не трогаются вообще. Удобно, когда плата ещё не в сети или звук не настроен.

```bash
sudo python3 run.py --config config.json --test diag    # ЧТО ИМЕННО НЕ ТАК: права, пины, занятость
sudo python3 run.py --config config.json --test matrix  # шаблоны: модули, яркость, битые пиксели
sudo python3 run.py --config config.json --test eyes    # глаза + анализатор
python3 run.py --config config.json --test encoder      # энкодер и кнопка
python3 run.py --config config.json --test all          # глаза + энкодер вместе
```

Дополнительно:

| Флаг | Зачем |
|---|---|
| `--duration N` | остановиться через N секунд (без него — до Ctrl+C) |
| `--simulate` | без железа: кадры в консоль символами `#` и `.` |
| `--brightness 0..15` | яркость матрицы (тесты по умолчанию светят на 15 — максимум) |
| `--driver sysfs\|spi\|sim` | принудительный драйвер матрицы (перекрывает конфиг) |
| `--cs 67 --din 64 --clk 66` | принудительные GPIO-линии, чтобы быстро перебрать пины |

Что смотреть:

| Тест | Что происходит | На что смотреть |
|---|---|---|
| `diag` | проверяет root, `/sys/class/gpio`, экспорт и переключение каждого пина, наличие `/dev/spidev*`, `gpiodetect`, `ffmpeg/aplay` | список `OK/FAIL` по каждому пину и готовый список проблем; код возврата `2`, если что-то не так |
| `eyes` | по кругу: «поиск сети» → блуждающие зрачки с реакцией на «биты» → показ `v NN` → «спящее» лицо | зрачки двигаются плавно, «рот» бежит, ничего не мерцает и не сдвинуто на модуль |
| `encoder` | каждое событие печатается и показывается на матрице: `turn` → счётчик на «рту», `press`/`release`, `hold` → `b NN` (яркость), `clicks N` → `E N` | один щелчок = один шаг, нет «дребезга» и пропусков, кнопка срабатывает с первого нажатия |
| `matrix` | заливка → по одному модулю слева-направо → ступеньки яркости → шахматка → полоски | **слева** загорается **первый** модуль (иначе модули подключены в обратном порядке); все точки горят, нет мёртвых столбцов; яркость меняется заметно |
| `all` | глаза живут, энкодер управляет лицом (вращение — громкость, клик — вкл/выкл, 2 клика — режим) | реакция «злого» взгляда и прищура, смена режима анализатора |

### Если ничего не светится

Идите строго по шагам — почти всегда причина в первых двух пунктах.

```bash
# 1. диагностика: она прямо скажет, что не так
sudo python3 run.py --config config.json --test diag
```

Что она проверяет и что делать по результату:

| Результат `diag` | Причина | Что делать |
|---|---|---|
| `1) права: НЕ root` | sysfs GPIO требует root | запускать через `sudo` (или добавить пользователя в группу `gpio`) |
| `2) sysfs GPIO: НЕТ` | ядро не отдаёт GPIO через sysfs | включить overlay `spi-spidev` и поставить `"driver": "spi"` |
| `FAIL ... GPIO N занят` | пин занят драйвером (overlay SPI/I2C/UART) | выключить overlay в `/boot/armbianEnv.txt` **или** перейти на `"driver": "spi"` |
| `FAIL ... export` | нет прав / пин не тот | `sudo`, затем проверить номера линий (`gpio readall`) |
| `OK` по всем пинам | дело не в GPIO | смотрите питание и провода (ниже) |

```bash
# 2. проверка шаблонами: тут видно, жива ли матрица вообще
sudo python3 run.py --config config.json --test matrix

# 3. если шаблоны не видны — попробовать максимум яркости и другой драйвер
sudo python3 run.py --config config.json --test matrix --brightness 15
sudo python3 run.py --config config.json --test matrix --driver spi     # если включён overlay
sudo python3 run.py --config config.json --test matrix --cs 65 --din 66 --clk 67
```

Железо (по частоте причин):

* **Питание.** MAX7219 рассчитан на **5 В** (минимум 4 В), от 3.3 В он либо не заведётся,
  либо будет еле светить. Питание берите с пина 5V (2 или 4), земля — общая с платой.
* **Логика 3.3 В при питании 5 В.** По даташиту `VIH = 0.7 × VCC = 3.5 В`, а у H3 выход
  3.3 В — на границе. С короткими проводами обычно работает; если нет — поставьте
  level shifter (74AHCT125/74HCT245) на DIN/CLK/CS.
* **Цепочка модулей.** `DIN` платы → `DIN` **первого** модуля, `DOUT` первого → `DIN` второго
  и так далее. Если воткнуть в `DOUT` — не загорится ничего.
* **Провода.** DIN/CLK/CS — обязательно, GND — обязательно. Плохой dupont-контакт
  даёт именно «тишину», а не мусор на экране.
* **Драйвер.** Либо `sysfs` (без overlay), либо `spi` (с overlay). Включённый overlay
  забирает PC0/PC2/PC3 себе, и `sysfs`-драйвер получит «busy».
* **Яркость.** В обычном режиме в конфиге стоит `2`, это довольно тускло; в тестах —
  `15`. Если видно только в тестах — поднимите `ui.brightness_mouth`/`brightness_eyes`.

Если в тестах всё работает, а в обычном режиме нет — проблема не в железе, а в
`audio.device`, Wi-Fi или путях к `ffmpeg`/`aplay`.

## Конфиг: `config.json`

Файл лежит рядом с программой, при установке копируется в `/etc/benderadio/config.json`.
После правок: `systemctl restart benderadio`.

### Станции

```json
"radio": {
  "station": 0,           // с какой станции начинать (если в state.json ещё пусто)
  "volume": 10,           // 0..volume_steps
  "volume_steps": 21,
  "stations": [
    { "name": "Radio 1 Rock", "url": "http://stream81.metacast.eu/radio1rock128" },
    { "name": "Европа Плюс",  "url": "https://ep128.hostingradio.ru:8030/ep128" }
  ]
}
```

Ссылок может быть сколько угодно, `name` показывается в логе. Подходят любые форматы,
которые умеет `ffmpeg`: MP3, AAC/AAC+, OGG/Vorbis, Opus, FLAC — и `http://`, и `https://`
(в отличие от ESP8266, здесь TLS не проблема). Все 6 станций в конфиге проверены рабочими.

### Wi-Fi

```json
"wifi": {
  "enabled": true,
  "ssid": "NewBuilding",
  "password": "MMH_new2023",
  "interface": "wlan0",
  "country": "RU",
  "connect_on_start": true
}
```

Как это работает:

* если интерфейс уже с IP — ничего не делает;
* если установлен **NetworkManager** (в Armbian по умолчанию) — `nmcli device wifi connect`;
* иначе через `wpa_supplicant`: пароль хешируется `wpa_passphrase`, пишется
  `/etc/wpa_supplicant/wpa_supplicant-wlan0.conf`, затем `dhclient`/`udhcpc`;
* нужны права root (сервис и так работает от root);
* если сеть не поднялась — программа не падает, продолжает крутить «поиск сети» и
  пробует снова раз в 30 секунд, когда поток отваливается.

Сменить сеть можно просто правкой `ssid`/`password` + `systemctl restart benderadio`.

### Звук

```json
"audio": {
  "device": "default",        // hw:1,0 для USB-карты, hdmi для HDMI (ALSA-имена)
  "sample_rate": 44100,
  "channels": 2,
  "buffer_us": 400000,        // буфер aplay, мкс (больше = стабильнее, но инертнее)
  "chunk_seconds": 0.02,      // размер чанка, с которым работает VU
  "ffmpeg": "ffmpeg",
  "aplay": "aplay",
  "volume_control": "amixer", // amixer | software | none
  "amixer_card": "",          // "" = карта по умолчанию, иначе номер из aplay -l
  "amixer_control": "PCM"     // имя из amixer scontrols
}
```

Найти устройства:

```bash
aplay -l                 # список карт: card 0, card 1 ...
aplay -L | head -40      # именованные устройства (default, sysdefault, hdmi, ...)
amixer scontrols         # имя регулятора громкости: PCM, Master, Speaker...
```

Если `amixer` не сработал, громкость автоматически уедет в «программную» (нужен `numpy`),
и в логе будет предупреждение.

### Матрица MAX7219

```json
"matrix": {
  "driver": "sysfs",                     // sysfs | spi | sim
  "modules": 5,
  "brightness": [2, 2, 2, 5, 5],         // стартовая яркость по модулям
  "gpio": { "chip": "gpiochip0", "cs": 67, "din": 64, "clk": 66, "half_period_us": 4 },
  "spi":  { "bus": 0, "device": 0, "speed_hz": 1000000 }
}
```

* `driver: sysfs` — работает без overlay'ев и пакетов: три пина дёргаются через
  `/sys/class/gpio`. Полный кадр ~20–40 мс, этого хватает (лицо обновляется 6 раз в секунду).
* `driver: spi` — быстрее и аккуратнее. Нужен overlay в `/boot/armbianEnv.txt`:
  ```
  overlays=spi-spidev
  param_spidev_spi_bus=0
  ```
  после перезагрузки появится `/dev/spidev0.0`.
* `driver: sim` — кадр в консоль.

#### sysfs или spi — как выбрать

`sysfs` и `spi` — это **не тип матрицы** (MAX7219 он и есть MAX7219, провода те же самые),
а способ, которым Orange Pi управляет пинами:

| | `sysfs` | `spi` |
|---|---|---|
| Как работает | программа сама дёргает GPIO | это делает драйвер SPI в ядре |
| Нужен overlay | нет | да, `overlays=spi-spidev` |
| Нужен `/dev/spidevX.Y` | нет | да |
| Скорость кадра | ~20–40 мс | доли миллисекунды |
| Пины | PC0/PC2/PC3 как обычные GPIO | те же PC0/PC2/PC3, но заняты ядром |
| Когда выбирать | «просто чтобы работало», без правки загрузчика | если overlay уже включён или нужна максимальная плавность |

Правило простое:

```bash
ls /dev/spidev*        # если файл есть — overlay включён, ставьте "driver": "spi"
                       # если нет — оставляйте "driver": "sysfs" (и overlay не включайте)
```

Смешивать нельзя: включённый overlay забирает PC0/PC2/PC3 у GPIO, и `sysfs` получит
«пин занят» — тогда матрица не светится вообще. Проверить, в каком вы состоянии:

```bash
sudo python3 run.py --config config.json --test diag
```

Если включён overlay, а в конфиге всё ещё `sysfs`, программа не будет молча ничего делать:
она напишет в лог, что пины заняты, найдёт `/dev/spidev*` и **сама переключится на SPI**
(отключается через `"auto_fallback": false` в секции `matrix`). Но правильнее поставить
`"driver": "spi"` руками.

Пакет `python3-spidev` при этом **не обязателен**: если его нет, используется встроенный
ioctl-бэкенд (`/dev/spidevX.Y` напрямую), так что SPI работает сразу после включения overlay.

Быстро попробовать другой драйвер, не трогая конфиг:

```bash
sudo python3 run.py --config config.json --test matrix --driver spi
sudo python3 run.py --config config.json --test matrix --driver sysfs
```

Номера линий GPIO: `банк_смещение + номер`, для H3: PA = 0, PB = 32, PC = 64, PD = 96, PG = 192.
То есть `PC0 = 64`, `PC2 = 66`, `PC3 = 67`.

### Энкодер

```json
"encoder": {
  "driver": "sysfs",          // sysfs | gpiod | sim
  "chip": "gpiochip0",
  "a": 6,                     // PA6
  "b": 1,                     // PA1
  "button": 0,                // PA0
  "button_active_low": true,  // кнопка на GND, внутренняя подтяжка
  "debounce": 0.02,
  "click_timeout": 0.35,
  "hold_time": 1.2
}
```

Проверить, что пины те, что вы воткнули: `gpio readall` (пакет wiringOP) или
`gpiodetect` / `gpioinfo` из libgpiod.

### Остальное

```json
"ui": {
  "state": true,                 // при первом запуске звук включён
  "brightness_mouth": 2,
  "brightness_eyes": 5,
  "analyzer_mode": 0,            // 0 = шум, 1 = столбики
  "noise_threshold": 20,         // порог тишины, 0..100
  "eye_interval": 0.15,          // как часто двигаются зрачки
  "analyzer_interval": 1.0,      // как часто перерисовывается «рот»
  "angry_timeout": 0.8,          // «злой» взгляд после кручения громкости
  "level": {
    "db_floor": -60,             // ниже этого — тишина
    "threshold": 20,
    "attack": 0.55,              // скорость атаки 0..1
    "release": 0.12,             // скорость спада 0..1
    "pulse_min": 30,             // гистерезис детектора бита, %
    "pulse_max": 80
  }
},
"storage": { "state_file": "/var/lib/benderadio/state.json" },
"logging": { "level": "INFO" }
```

Ориентир: разъём 2×20, **1-й пин** — у края платы рядом с micro-USB. Все пины, которые
использует программа, выделены жирным.

| Пин | H3 | Линия GPIO | Что подключаем |

| 2 | 5V | — | **питание MAX7219 (+5 В)** |
| 3 | PA12 | 12 | — |
| 4 | 5V | — | резерв питания |
| 5 | PA11 | 11 | — |
| 6 | GND | — | **общая земля: матрица + энкодер** |
| 7 | PA6 | 6 | **энкодер S1 (CLK/A)** |
| 8 | PA13 | 13 | — |
| 9 | GND | — | земля |

### Схема подключения

```
Orange Pi One                    MAX7219: цепочка из 5 модулей
                                    (CLK и CS идут ПАРАЛЛЕЛЬНО на все модули,
                                     DIN/DOUT — ПОСЛЕДОВАТЕЛЬНО)

19  PC0  (MOSI) ───────────────► DIN [M0] DOUT ─► DIN [M1] DOUT ─► [M2] ─► [M3] ─► [M4]
23  PC2  (CLK)  ──┬─► CLK  всех модулей
24  PC3  (CS)   ──┼─► CS   всех модулей
 2  5V          ──┼─► VCC  всех модулей
 6  GND         ──┴─► GND  всех модулей

Энкодер (вторые выводы S1/S2 — на GND, кнопка — на GND)
 7  PA6  ──► S1 (CLK / A)
11  PA1  ──► S2 (DT  / B)
13  PA0  ──► кнопка
 6  GND  ──► общий

Звук: USB-звуковая карта (или HDMI). К GPIO не подключается.
Анализатор: НЕ подключается — уровень считается из самого аудиопотока.
```

**M0 — это модуль, к которому приходит DIN с платы.** В коде M0…M2 — «рот»/анализатор
(левые 24 точки), M3…M4 — «глаза» (правые 16). Если после сборки лицо оказалось
зеркальным (глаза слева), не перепаивайте: поставьте в конфиге

```json
"matrix": { "reverse": true }
```

### Питание и уровни (частые грабли)

* **MAX7219 питается от 5 В** (минимум 4 В). От пина 3.3 В он не заработает.
* 5 модулей на яркости 15 — это до ~1 А. Надёжнее отдельный БП **5 В ≥ 2 А**,
  земля обязательно соединена с землёй платы (GND, пин 6).
* **Логика 3.3 В при питании 5 В** — на границе допуска (`VIH = 0.7 × VCC = 3.5 В`).
  С короткими проводами обычно работает. Если мигает/не заводится — поставьте
  level shifter (74AHCT125 / 74HCT245) на DIN/CLK/CS.
* Провода: DIN/CLK/CS — минимум 3 сигнальных, но **без GND работать не будет**.
* **Подтяжки энкодера**: в режиме `driver: sysfs` программа не может включить внутренние
  подтяжки. Если кнопка «не видит» нажатий или энкодер скачет — поставьте резисторы
  **10 кОм** с линий 7/11/13 на 3.3 В (пин 1 или 17), либо переключитесь на
  `"encoder": { "driver": "gpiod" }` (пакет `python3-libgpiod` включает подтяжки сам).
  Конденсаторы 100 нФ с S1/S2/кнопки на GND заметно уменьшают дребезг.

### Звук

* **USB-звуковая карта**: `aplay -l` покажет `card 1`, в конфиге `"device": "hw:1,0"`.
* **HDMI**: `"device": "hdmi"` (или `hw:0,0`), если в системе есть HDMI-звук.
* **Питание платы**: micro-USB 5 В ≥ 2 А. При слабом питании Wi-Fi-донгл отваливается.

## Управление

| Действие | Что делает |
|---|---|
| Вращение энкодера | громкость (0…21), на «рту» `v NN` |
| Короткий клик | вкл/выкл звук (при выключении матрица гаснет) |
| 2 клика | режим анализатора (шум ↔ столбики) |
| 3 клика | автоподстройка порога тишины (`E NN`) |
| Зажать кнопку + вращать | выбор станции (`s NN`), поток перезапускается при отпускании |
| Зажать кнопку на 1.2 с | режим яркости: вращение меняет яркость `b NN` («рот»); ещё одно удержание — `o NN` («глаза»); выход — клик или 8 с бездействия |

Настройки (громкость, станция, режим, яркость, порог) сохраняются в
`/var/lib/benderadio/state.json` и переживают перезагрузку.

## Отладка

```bash
# все подробности
python3 run.py --config config.json --log-level DEBUG

# только конфиг/логика, без GPIO и звука
python3 run.py --config config.json --simulate --duration 5

# самопроверка
python3 run.py --config config.json --selftest

# железо по отдельности, без сети и звука
python3 run.py --config config.json --test matrix
python3 run.py --config config.json --test eyes
python3 run.py --config config.json --test encoder

# посмотреть, что видит звук
aplay -l; amixer scontrols; speaker-test -D hw:1,0 -c2 -t sine -l 1
```

Типичные проблемы:

| Симптом | Причина / лечение |
|---|---|
| **Горит всё сразу и яркость не меняется** | включён test mode `0x0F` — обычно из-за неверного порядка байт в SPI-потоке (адрес должен повторяться на каждый модуль); в этой версии исправлено |
| `aplay отвалился` | неверный `audio.device`; проверьте `aplay -l` и попробуйте `hw:X,0` |
| `нет прав на /var/lib/benderadio` | запуск не от root; сервис запускается от root |
| Матрица «мигает ерундой» | проверьте полярность CS и порядок модулей (первый модуль = левый) |
| `GPIO busy` / `export` не работает | включён overlay SPI, а драйвер `sysfs`; выберите что-то одно |
| Энкодер крутится «не туда» | поменяйте местами `a` и `b` (или переверните провода) |
| Звук рвётся | увеличьте `buffer_us` до 600000, проверьте питание и Wi-Fi |
| Громкость не меняется | неверный `amixer_control`; `amixer scontrols` покажет имя |

## Чем это отличается от ESP-прошивки

| | ESP8266/ESP32 | Orange Pi One |
|---|---|---|
| Звук | ESP8266Audio / ESP32-audioI2S | `ffmpeg` → `aplay` (любой кодек, HTTPS) |
| Потоки | MP3, без TLS (на ESP8266) | MP3/AAC/OGG/Opus/FLAC, http и https |
| Анализатор | ADC-пин (шум, делитель) | RMS прямо из PCM (точно и без проводов) |
| Настройки | EEPROM | JSON-файл |
| GPIO | регистры портов | sysfs / SPI / libgpiod |
| Wi-Fi | встроенный | USB-донгл + nmcli/wpa_supplicant |
| Обновление | перепрошить | поменять `config.json` и `systemctl restart` |
